# AGENTS.md — `tsundoku`

## Mission
Build and maintain `apps/tsundoku`: a camera-assisted ISBN scanner UI backed by Cloudflare Worker API routes (`POST /api/isbn-lookup`) that resolve authoritative book metadata via a catalog-first pipeline (Open Library primary, Google Books fallback) and, for paid users, optionally enrich metadata (such as a concise summary) via Featherless AI according to `SPEC.md`. The scanner offers three modes: `Scan ISBN` (default), `Enter Book Title` (a manual title/author catalog search for every user via `POST /api/title-lookup`), and `Read Cover with AI` (Paid-Registered-only, `POST /api/books/extract-cover`, which reads the cover with a Featherless vision model and verifies it against the catalog).

## Source of Truth
- Functional requirements, contracts, and acceptance criteria: `SPEC.md`
- Request/response runtime validation: `@repo/book-schemas` (`packages/domains/books/book-schemas`)
- Three-tier entitlement model: `src/lib/entitlements.ts` (single source of truth for `resolveUserTier`, `canUseAi`, and `enforceAiAccess`); the paid tier's "unlocked" state is a **positive credit balance**, held in `credit_ledger` and read via `src/lib/llm-entitlement.ts` + `src/lib/credits.ts`.
- Do not invent undocumented endpoints, environment variables, or response fields. Update `SPEC.md` and schemas first if a contract changes.

## Pipeline (Catalog-First, Then LLM Enrichment)
`POST /api/isbn-lookup` resolves a book in strict order:
1. **Validate** the ISBN-10 / ISBN-13 (format + check digit) via `@repo/isbn` (`packages/domains/books/isbn`). Invalid input -> `400 INVALID_ISBN`.
2. **Catalog (authoritative)** via `src/lib/catalog.ts`: query Open Library first, then Google Books (`q=isbn:<isbn>`, with optional `GOOGLE_BOOKS_API_KEY`) only when Open Library has no match. Catalog `title` / `authors` are authoritative (`verified: true`, `source` = `openlibrary` | `google-books`). No match anywhere -> `422 BOOK_NOT_FOUND`; every provider failing -> `502 UPSTREAM_ERROR`.
3. **Enrich (best-effort, optional)** via `src/lib/featherless.ts`: only for **Paid-Registered** callers (signed in **and** `has_llm_unlock`) who have also opted in with the `enrich_with_llm` preference. It uses `FEATHERLESS_MODEL` to add a concise `summary` (and optional `topics`) without ever overwriting verified `title` / `authors`. A missing key, a failure, or unusable output degrades gracefully to `enriched: false`; enrichment never fails the lookup, and free tiers never reach Featherless.

## Scanner Modes — Phase 8
The ISBN Scanner page (`/`) has a **Mode** radio group with three options; selecting a mode swaps its panel and only one camera ever runs at a time. The main page `<h1>` (`#page-heading`) also tracks the active mode: `ISBN Scanner` (`Scan ISBN`), `Manual Entry of Book Title` (`Enter Book Title`), and `Read Title from Book Cover by AI` (`Read Cover with AI`).
1. **`Scan ISBN` (default):** **auto-starts** the live camera (no "Start Camera" step) and runs a **continuous** barcode loop that never pauses. Each **newly detected** ISBN (differing from the code already in the input) is written into **Manual ISBN** and turns the **Look up** button green; the user taps **Look up** to resolve it (`POST /api/isbn-lookup` → catalog → save, all three tiers) and render `Match found`. A miss shows a clear no-match/error message and clears the stale card. A denied permission / `getUserMedia` failure shows an error with a **Retry Camera** button. There is no manual Start/Stop/Scan-Frame/Scan-Next control in the active state.
2. **`Enter Book Title` (all three tiers):** stacked (never side-by-side) **Title** (required) and **Author (optional)** inputs plus a **Search** button and a **Just Save It** button. **Search** posts `{ title, author? }` to `POST /api/title-lookup` (Open Library `search.json` first, then Google Books `intitle:`/`inauthor:` refined then plain `q=`), renders the best matching edition into this mode's read-only `Match found` card (`confidence: "high"` with an ISBN, `"medium"` without), **and** populates its own **Possible Book Titles** list from the returned `editions` (mirroring `Read Cover with AI`); an empty result shows a clear no-match message inviting a retry. **Just Save It** renders the typed title/author as a user-confirmed manual entry (`source: "manual"`, `verified: false`, `confidence: "high"`) with provenance `Source: manual entry · not verified · not enriched · Confidence: high` and clears the now-stale candidate list.
3. **`Read Cover with AI` (Paid-Registered only):** selecting the mode **opens the live camera immediately** (no separate trigger button), mirroring `Scan ISBN`. It uses `navigator.mediaDevices.getUserMedia` (preferring the rear/`environment` lens where supported) with a single **Capture** control. Pressing **Capture** grabs the current frame to an offscreen `<canvas>`/blob **without** calling `track.stop()`, clearing `video.srcObject`, or hiding the `<video>` — so the live viewfinder keeps streaming during the read and after the result, and the user can re-frame and capture again. **Capture** is disabled only while the request is in flight (`Reading cover…`), then re-enabled; there is **no intermediate "Use photo" / "Retake" confirmation**. The OS file picker (`<input type="file">`) is used **only as a fallback** when the camera is unsupported, permission is denied, or no device is present. Free-Unregistered / Free-Registered users are prompted to sign in or unlock the **$0.99** tier; Paid-Registered users get the frame down-scaled on a `<canvas>` (longest edge ≤ 1024 px, JPEG quality `0.8`) and posted to `POST /api/books/extract-cover`.
4. **`POST /api/books/extract-cover` is a complete single-pass pipeline:** the vision model's `title`/`isbn` are treated as **hints**, promoted to canonical `title`/`authors`/`publisher`/`isbn` via a catalog lookup (`source` = `catalog_lookup` | `vision_only`); a vision title carrying the author's name as a possessive prefix (e.g. `"Chris Guillebeau's The $100 Startup"`) has the prefix stripped and the cleaned title is tried as a second search candidate. When a catalog ISBN resolved and the caller's `enrich_with_llm` preference is on, the summary enrichment is applied **inside the same request**. The strict response is `{ title, subtitle, authors, publisher, publishedYear, isbn, summary, enriched, source, provider, confidence, candidates }` — `candidates` is the `CatalogEdition[]` behind the match (rendered client-side as **All Possible Book Titles**, `[]` when nothing was searched) — so it is the **single source of truth** for a cover read: the client performs **no follow-up lookup**.
5. **"All Possible Book Titles" disambiguation (both `Read Cover with AI` and `Enter Book Title`):** catalog candidate editions populate an editable list inside the mode's own panel — from `extract-cover`'s `candidates` for cover reads, and from `/api/title-lookup`'s `editions` for title searches: each row is **Title** / **Author (optional)** / **ISBN (optional)** + **Select** (the three text inputs reuse the same `field-input` rule as the **Manual ISBN** box, and **Select** reuses **Look up**'s `field-button` rule) — a single row seeded from the raw hint/typed title when the catalog returned nothing, with the helper text `"Edit a row and tap Select to use that book instead."`. On **Select**, a provided ISBN wins (`POST /api/isbn-lookup`), else `Title` + `Author` go to `POST /api/title-lookup`; the resolved canonical book updates that mode's read-only `Match found`. An empty/invalid/no-match combination shows the ephemeral `"That is not a valid combination. Check the combination and try again."` message, cleared on the next successful lookup or next capture.
6. **`Match found` is read-only and scoped per mode:** each of the three modes owns an **independent** `Match found` container (and its own status/loading state), so switching modes shows **only** the active mode's card — the others are hidden, not discarded, and reappear untouched when the user switches back. The heading is always the plain **`Match found`** (the scope comes from rendering into that mode's own container, not from the heading text). Any resolved book — from a barcode scan, a title search, or a cover read — renders as a **non-editable** card (users who want to edit switch to `Enter Book Title`), showing title/author/publisher/year/summary, an optional `ISBN-13`, the provenance line, and a **Save** action. The primary action buttons (**Save to my shelf**/**Save on this device**, **Select**) reuse the same `field-button` rule as **Look up** / **Search** / **Just Save It** (identical height, padding, border radius, border/fill, and hover/active states), with `.action-button` only adding full width for the buttons that sit outside a stretched `.controls` flex row; the **Manual ISBN** input and the candidate inputs share the `field-input` rule. A `vision_only` read renders the grounded hints (unverified, `confidence: "low"`) with a status noting no catalog match was found. A confirmed manual entry is saved as a `SaveableBook` (`source: "manual"`, synthetic `manual:<slug>-<hex>` id) — to `localStorage` for Free-Unregistered (stateless, no D1 write) or via `POST /api/sheets/save-book` for registered users.
7. **Per-mode status bar + camera lifecycle:** each mode owns its own instructional/status bar placed inside its panel — directly **below the camera viewfinder** in `Scan ISBN` (`#status-isbn`) and `Read Cover with AI` (`#status-cover`), and **above the "No barcode? …" hint** in `Enter Book Title` (`#status-title`); `setStatus()` writes to the active mode's bar. The two camera modes (`Scan ISBN`, `Read Cover with AI`) never run at once. Switching modes (`applyMode`) stops the loop that no longer applies and releases the previous mode's tracks (`releaseStream()` / `releaseCoverStream()` call `track.stop()` on every track and null `video.srcObject`); each mode's `Match found` card and **All Possible Book Titles** list live inside its panel, so a switch hides — but never discards — them. `pagehide` releases every stream so no track is left active in the background.

## Three-Tier Entitlements (Enforced in UI + API)
Resolve every caller through `src/lib/entitlements.ts`; the paid tier's gate is a **positive credit balance** (`credit > 0`), read via `readShelfEntitlement(db, userId)` in `src/lib/llm-entitlement.ts` (which derives `hasLlmUnlock` from the `credit_ledger` sum, failing closed to locked on any D1 error):
- **Free-Unregistered** (`!session.userId`): stateless client-only (local state / `localStorage`, **no D1 reads or writes**). Allowed: `Scan ISBN` barcode lookup and manual Title/Author catalog search. No AI.
- **Free-Registered** (`session.userId`, no remaining credit): D1-backed shelf/group features plus everything above. No AI.
- **Paid-Registered** (`session.userId` **and** `creditBalance > 0`): adds both AI features — `FEATHERLESS_MODEL` summaries and `FEATHERLESS_VISION_MODEL` cover reading — each deducting its configured per-action credit rate.
Server routes call `enforceAiAccess({ userId, hasLlmUnlock })` **before** touching Featherless, returning `401 UNAUTHENTICATED` (anonymous) or `403 LLM_LOCKED` (signed in without remaining credit), and fail closed on a D1 read error so a free tier can never reach the LLM.

## Credit Metering & Billing
- `src/lib/credits.ts` is the single source of truth: `credit_ledger` is append-only with a **signed** `amount` (top-ups `+`, usage `-`), so `getCreditBalance` = `SUM(amount)` and `getCreditSummary` yields auditable `{ totalAdded, totalUsed, balance, usageByAction[] }`.
- Per-action rates come from bindings via `resolveCreditRates(env)` with documented defaults: `CREDIT_RATE_BOOK_SUMMARY` (`0.00001`, single summary), `CREDIT_RATE_BATCH_BOOK_SUMMARY` (`0.00010`, per book in a batch), `CREDIT_RATE_BOOK_TITLE_IMAGE` (`0.00005`, cover/title image). A blank/invalid binding falls back to the default; a zero rate records no usage row.
- Every AI action deducts and records usage (`recordUsage`) with its resolved rate: `POST /api/isbn-lookup` (single summary), `POST /api/shelves/batch-enrich` (per book), `POST /api/books/extract-cover` (per cover read). Metering is best-effort and never fails the AI response.
- Top-ups: `POST /api/shelves/checkout` persists a `pending` `credit_payments` row and returns a return URL carrying the unique reference; top-ups are **repeatable** (a user with existing credit is charged again — there is no `alreadyUnlocked` short-circuit) and the optional JSON body field `returnTo` selects the return path (default `/`, sanitised to a same-origin bare path). `POST /api/shelves/reconcile-payment` confirms the payment against HitPay's `GET /payment-requests/{id}` and credits idempotently; `POST /api/webhooks/hitpay` credits on a verified `completed` payment. `addCredit` is `INSERT OR IGNORE` on the unique reference, so replays never double-credit.
- UI: `/settings` shows a **Billing & Metering** section (total added / remaining / total usage + per-action breakdown / current rates) plus a **"Top up AI credits — $0.99"** button that stays visible/enabled at any balance (repeatable). On `/`, the unnamed scanner section groups the **Mode** radio (`Scan ISBN` / `Read Book Title`) with the **`Enrich book info with LLM`** (`Yes`/`No`) radio sitting directly below it (no separate "AI features" panel). The **"Unlock AI features for $0.99"** button is shown **only** at a zero/unset balance (signed in); at any positive balance it is hidden. The `Payment of $0.99 is successful. AI credit remaining: $<balance>.` banner is server-rendered **hidden** and is **ephemeral** — un-hidden **only** by the live top-up confirmation path (the `?unlock=return` reconcile poll or an entitlement re-read that observes an increased balance), so it never persists or reappears on a reload.

## Stack & Runtime Constraints
- Monorepo package manager: `pnpm` (never `npm` or `npx` for workspace commands).
- Framework & adapter: Astro with `@astrojs/cloudflare` running on `workerd`.
- Secrets & config: `FEATHERLESS_API_KEY`, `FEATHERLESS_MODEL` (text summaries), `FEATHERLESS_VISION_MODEL` (cover reading), optional `GOOGLE_BOOKS_API_KEY`, the HitPay payment secrets (`HITPAY_API_KEY`, `HITPAY_SALT`, `HITPAY_API_URL`, optional `HITPAY_CURRENCY`), and the credit-rate bindings (`CREDIT_RATE_BOOK_SUMMARY`, `CREDIT_RATE_BATCH_BOOK_SUMMARY`, `CREDIT_RATE_BOOK_TITLE_IMAGE`) must only be read on the server/Worker side (`cloudflare:workers` `env` / runtime context), never exposed to `src/pages/index.astro` or client scripts.
- Catalog-first rule: Catalog sources (`openlibrary`, `google-books`) own verified `title` and `authors`; LLM enrichment must never overwrite verified `title` or `authors`.
- TypeScript: strict mode; no `any` unless justified and isolated at external boundaries.
- Match the Astro + Cloudflare Workers setup, script names, and config conventions in `apps/client-x` (`package.json`, `astro.config.mjs`, `wrangler.jsonc`, `tsconfig.json`).

## Project Structure
Shared, framework-agnostic domain code lives in workspace packages; app-specific code stays under `apps/tsundoku`.
- `@repo/book-schemas` (`packages/domains/books/book-schemas`) — Zod request/response, catalog, enrichment, cover-extraction, and error schemas
- `@repo/isbn` (`packages/domains/books/isbn`) — Pure ISBN normalization, validation, and ISBN-10 to ISBN-13 conversion
- `src/lib/entitlements.ts` — Three-tier entitlement model (`free-unregistered` / `free-registered` / `paid-registered`), `LLM_UNLOCK_PRICE_USD`, `LLM_UNLOCK_CURRENCY`, and `enforceAiAccess`
- `src/lib/credits.ts` — Credit metering & billing: `credit_ledger` / `credit_payments` accessors (`getCreditBalance`, `getCreditSummary`, `addCredit`, `recordUsage`, `resolveCreditRates`, `rateForAction`, `formatCredit`, payment persistence/lookup)
- `src/lib/llm-entitlement.ts` — Single-source AI entitlement helper (`readShelfEntitlement` → `{ hasLlmUnlock, enrichWithLlm, creditBalance }` where `hasLlmUnlock = creditBalance > 0`, `isLlmUnlocked`, `buildUnlockReference` / `parseUnlockReference`); every UI gate, AI route, and payment fulfillment reads the entitlement through this module
- `src/lib/hitpay.ts` — Injectable HitPay client (`createHitPayPaymentRequest`, `getHitPayPaymentRequest`) and webhook `verifyHitPaySignature` (HMAC-SHA256 over the raw body)
- `src/lib/catalog.ts` — Injectable catalog lookup client (Open Library primary, Google Books fallback), including title/author `searchEditions`; also used by `extract-cover` to promote vision hints to canonical metadata
- `src/lib/featherless.ts` — Injectable Featherless AI client (text summaries + multimodal `extractCover`, which returns grounded-only cover hints incl. an `isbn` lookup hint)
- `src/lib/manual-book.ts` — Pure no-ISBN fallback helpers (`buildManualBook`, synthetic `manual:<slug>-<hex>` id)
- `src/lib/local-shelf.ts` — Stateless `localStorage` shelf for Free-Unregistered users (no D1)
- `src/lib/scanner.ts` — Modular barcode/ISBN candidate extraction helpers
- `src/lib/shelf-configs.ts` — D1 `shelf_configs` accessors (incl. `enrich_with_llm`, `has_llm_unlock`)
- `src/pages/index.astro` — Camera + manual ISBN fallback UI and the `Scan ISBN` / `Read Book Title` mode switch (with tier-gated `Read Cover with AI`)
- `src/pages/api/isbn-lookup.ts` — Cloudflare Worker `POST /api/isbn-lookup` route
- `src/pages/api/title-lookup.ts` — Cloudflare Worker `POST /api/title-lookup` route (title/author edition search)
- `src/pages/api/books/extract-cover.ts` — Paid-Registered-only `POST /api/books/extract-cover` route; a **complete single-pass** cover pipeline (vision hint → catalog promotion → optional in-request LLM summary enrichment) whose `CoverLookupResponse` is the single source of truth for the client
- `src/pages/api/shelves/checkout.ts` — Signed-in-only `POST /api/shelves/checkout` route (creates a HitPay payment request for the $0.99 credit top-up and persists a pending payment)
- `src/pages/api/shelves/reconcile-payment.ts` — Signed-in-only `POST /api/shelves/reconcile-payment` route (confirms a returned payment via HitPay's status API and credits the ledger idempotently)
- `src/pages/api/shelves/entitlement.ts` — `GET /api/shelves/entitlement` route (client re-read of the credit balance / unlock state after the HitPay redirect)
- `src/pages/api/webhooks/hitpay.ts` — `POST /api/webhooks/hitpay` route (verifies the `Hitpay-Signature` HMAC and idempotently credits the top-up)
- `src/pages/settings.astro` — Account settings page (incl. the **Billing & Metering** section)
- `src/test/*.test.ts` — Vitest unit and endpoint tests
